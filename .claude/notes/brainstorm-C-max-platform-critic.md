## Часть 1. Что реально умеет MAX

### 1.1 Bot API — [DOC] https://dev.max.ru/docs-api
- **Домен** `platform-api2.max.ru`, токен только в заголовке `Authorization`. Лимит **30 rps** на весь API; **≤2 сообщения/ответа в секунду в один диалог/чат/канал** ([POST /messages](https://dev.max.ru/docs-api/methods/POST/messages)) → для рассылок нужна очередь.
- **Сообщения**: текст до **4000 символов**, `format: markdown|html` (жирный, курсив, подчёркивание, выделение `^^`, заголовки, цитаты, упоминания `max://user/<id>`), `notify` (можно слать без пуша), `disable_link_preview`. Можно отправлять, **редактировать и удалять** сообщения, закреплять сообщения в чате.
- **Типы кнопок inline-клавиатуры**: `callback`, `link` (до 2048 символов), `request_contact` (телефон + `hash` для проверки через HMAC-SHA256 с токеном), `request_geo_location`, `open_app` (открыть мини-приложение), `message` (отправить заготовленный текст), `clipboard` (скопировать в буфер). Лимит: до 210 кнопок, 30 рядов, до 7 в ряду (для link/open_app/geo/contact — до 3 в ряду).
- **Ответ на callback** `POST /answers`: обновить исходное сообщение и/или показать одноразовое уведомление ([DOC](https://dev.max.ru/docs-api/methods/POST/answers)) → «живые» карточки статуса без засорения чата.
- **Вложения**: image (≤50 МБ), video (≤250 МБ), audio (≤256 МБ / 60 мин), file (≤4 ГБ), sticker, location, share, до 12 вложений.
- **События**: `bot_added`, `bot_started`, `message_created/edited/deleted`, `message_callback`, `comment_created/edited/removed` (комментарии к постам канала — август 2026).
- **Чаты/каналы**: бота можно добавлять в групповые чаты (настраивается — [FAQ](https://dev.max.ru/help/chatbots)), управлять админами, закрепами, описанием. **`GET /chats` не поддерживается с июня 2026**, `POST /chats/{id}/members` ограничен с 9.09.2026 ([changelog](https://dev.max.ru/docs-api/changelog-api)) → бот не может сам собрать класс в чат, список чатов надо копить из событий `bot_added`.
- **Команды**: `PATCH /me/commands` (июль 2026) — меню команд.
- **Доставка событий**: Webhook (только HTTPS с доверенным сертификатом, HTTP и самоподписанные запрещены с 25.05.2026) или Long Polling `GET /updates` («для разработки/тестирования», ограничен по скорости и сроку хранения событий). **Webhook и long polling не работают одновременно** [3P].
- **Диплинки** [DOC](https://dev.max.ru/help/deeplinks): `https://max.ru/<bot>?start=<payload>` (payload ≤128 символов) и `https://max.ru/<bot>?startapp=<payload>` (≤512), `https://max.ru/:share?text=...` — экран «Отправить в MAX» с готовым текстом.

### 1.2 Мини-приложения и MAX Bridge — [DOC] https://dev.max.ru/docs/webapps/bridge
- Мини-апп **не существует без бота**, открывается кнопкой `open_app`, кнопкой в профиле бота или `?startapp=`. Только HTTPS, URL ≤1024 символа, прописывается в настройках бота в партнёрской платформе ([DOC](https://dev.max.ru/docs/webapps/introduction)). Одновременно открыт только один мини-апп.
- `initData` (подписанная строка для валидации на сервере), `initDataUnsafe` (user, chat, `start_param`), `platform` (ios/android/desktop/web), `version`, `deviceName`, `getLaunchContext()`.
- `requestContact()` — телефон с hash-проверкой.
- `openCodeReader()` — **QR-сканер** (камера или файл). Ограничения по платформам в доке не указаны → **[ASSUME] в веб-версии может не работать, нужен фолбэк**.
- `shareContent()` — нативный шеринг наружу (**не в вебе**); `shareMaxContent()` — отправить текст/сообщение в чат MAX; `openLink()`, `openMaxLink()` (открыть диплинк MAX внутри клиента); `downloadFile()` (только в клиенте MAX).
- `DeviceStorage` / `SecureStorage` (≤10 ключей) — **не в вебе**.
- `BiometricManager`, `HapticFeedback` — **только мобильные** (нет desktop/web).
- `requestScreenMaxBrightness()` на 30 с — удобно для показа QR на экране для сканирования.
- `ScreenCapture` (запрет скриншотов), `enableClosingConfirmation`, `BackButton`, `NfcManager` (только Android).
- **Геолокации в Bridge нет**. Есть кнопка бота `request_geo_location` [DOC]; в мини-аппе — только браузерный `navigator.geolocation` [ASSUME, работа в WebView MAX не подтверждена].
- **Пушей от мини-аппа в доке нет** [ASSUME: нельзя] → напоминания отправляет бот. Это честное обоснование связки «бот + мини-апп».
- **MAX UI** — `@maxhub/max-ui` (React, TypeScript), [github.com/max-messenger/max-ui](https://github.com/max-messenger/max-ui), версия 0.1.x — молодая библиотека, закладывать время на обходы. Есть Figma-гайдлайны ([changelog платформы](https://dev.max.ru/docs/changelog-platform)).

### 1.3 Экосистема и контекст
- **Сферум полностью в MAX** (учебные чаты классов/родителей, «Справка в школу», «Сбор файлов», расписание/дневник) [3P: sferum.ru, techora.ru, август 2026]. **Публичного API Сферума для сторонних ботов не найдено** [ASSUME] → «интеграция со Сферумом» = бот/диплинк в чате класса Сферума, а не чтение журнала. Внимание: «Сбор файлов» Сферума — прямой конкурент идей «собрать документы с родителей».
- Публикация ботов — только верифицированные юрлица/ИП/самозанятые, модерация до 48 ч [DOC FAQ, 3P Habr]. Для нас токен дают организаторы, но **URL мини-аппа прописывается в настройках бота → нужно заранее уточнить у организаторов, кто и как это делает** [ASSUME: риск].

### 1.4 Что даёт «платформенный бонус» (+0,15, всё или ничего)
Условия из ТЗ: сверх минимума, с пользовательской ценностью, органично, работает end-to-end, описано. Свой API и «больше функций» — не основание.

| Механика | Ценность, которую можно показать | Риск |
|---|---|---|
| Диплинк `?start=`/`?startapp=` с контекстом (QR на плакате, ссылка в чате класса) | ноль ввода: человек попадает сразу в нужное событие/форму | низкий, работает везде |
| `request_contact` с проверкой hash | подтверждённый телефон родителя/наставника без SMS | низкий |
| `shareMaxContent` / `:share?text=` | педагог в 1 тап отправляет приглашение в чат класса | низкий |
| `callback` + `/answers` (редактирование карточки) | живой статус без спама | низкий |
| `openCodeReader` | отметка присутствия / приём сдачи по QR | средний: web-фолбэк обязателен |
| `requestScreenMaxBrightness` | показ QR-пропуска ребёнка на экране | низкий, мелочь |
| `HapticFeedback`, `BiometricManager` | слабая ценность в образовании, «галочка» | жюри раскусит |
| Бот в групповом чате (`bot_added`) | сводки/напоминания прямо в чате класса | средний: права, что бот видит в группе [ASSUME] |

**Трудно/невозможно:** читать данные Сферума/дневника; добавлять людей в чаты ботом; писать пользователю, который не нажал «Старт» [ASSUME: скорее всего нельзя]; пуши из мини-аппа; геолокация в мини-аппе (не гарантирована); платежи (в доке не найдены); webhook у жюри на локальном Docker (нет публичного HTTPS) → **для проверяемости через `docker compose up` практичнее long polling** с флагом переключения на webhook в проде.

## Часть 2. Идеи, где MAX усиливает ценность

### Идея 1. «Допуск» — согласия и готовность к выездным мероприятиям (профпробы, экскурсии, соревнования)
**Проблема:** Классный руководитель 5–9 классов, который везёт группу на профпробу на предприятие (Единая модель профориентации) или на соревнование, хочет за 3–5 дней получить от всех родителей согласие, контакт на день выезда и важные сведения (аллергия, «заберу сам»), но собирает это вручную в чате класса и бумажках, из-за чего часть детей не едет из-за потерянной бумажки, а педагог тратит часы на «напомните ещё раз» и рискует выехать без подтверждений. *(Масштаб боли — гипотеза, подтвердить интервью с 5–10 классными руководителями и координаторами профминимума.)*
**Сценарий:** педагог в мини-аппе создаёт событие (дата, место, шаблон формы) → бот формирует диплинк `?startapp=event_x` и педагог через `shareMaxContent` публикует его в чат класса Сферума → родитель открывает, выбирает ребёнка, подтверждает телефон `request_contact`, отмечает согласие и поля → педагог видит живую доску «да / нет / не ответили» → бот сам напоминает **только не ответившим** (за 48 и 24 ч) → в день выезда педагог отмечает присутствие в боте кнопками или по QR, родители получают уведомление «ребёнок на месте / вернулся».
**Бонус MAX:** диплинк с контекстом + шеринг в чат класса + request_contact с проверкой + адресные напоминания ботом + (опционально) QR-отметка с фолбэком кнопками.
**MVP (2 роли, 1 сценарий):** создание события из шаблона, форма родителя, доска статусов, 2 напоминания, отметка присутствия. Won't: юридически значимая ЭП, интеграция с журналом, оплата. Явно указать: согласие в MVP — «подтверждение намерения», бумажный/ПЭП-документ — вне MVP.
**Масштабирование:** ядро = «событие + ростер + форма + статусы + напоминания»; переменная часть = шаблоны документов по региону/типу организации (школа → колледж → доп. образование → летний лагерь).

### Идея 2. «Практика без хвостов» — трекер производственной практики студента СПО
**Проблема:** Студент 2–3 курса колледжа, выходящий на производственную практику, хочет вовремя оформить договор/направление, вести дневник и получить подпись и характеристику наставника с предприятия, но документы ходят между студентом, руководителем практики от колледжа и наставником предприятия, который не пользуется системами колледжа, из-за чего сроки срываются, дневник заполняется задним числом, а зачёт откладывается. *(~4 млн студентов СПО — факт из ТЗ; частота срывов — гипотеза.)*
**Сценарий:** руководитель практики загружает группу и шаблон этапов → студент получает чек-лист с дедлайнами и ежедневное напоминание «1 строка в дневник» (бот) → наставник предприятия получает диплинк `?start=mentor_x`, **без регистрации** подтверждает телефон и раз в неделю жмёт «присутствовал / замечания» → по итогу наставник заполняет короткую характеристику в мини-аппе → руководитель видит светофор по группе.
**Бонус MAX:** нулевой онбординг внешнего участника (наставник) через диплинк + request_contact; ежедневные напоминания; мини-апп для характеристики.
**MVP:** 3 роли — это тяжелее; можно урезать до «студент + наставник», руководитель видит сводку в боте. Won't: генерация официальных документов, интеграция с АИС колледжа.
**Масштабирование:** ядро = «этапы + участники + подтверждения»; переменное = шаблоны специальностей/ФГОС, колледж → вуз, практика → стажировка VK Education.

### Идея 3. «Сказали — сделали» — сбор обратной связи с закрытием петли
**Проблема:** Заместитель директора / организатор мероприятия хочет понимать, что мешает ученикам и родителям, но опросы в Google Forms собирают 5% ответов, а люди не видят, что с их ответами что-то сделали, из-за чего на следующий опрос не отвечают вообще, а повторяющиеся проблемы не всплывают.
**Сценарий:** QR/диплинк на выходе с мероприятия → 2 кнопки + опциональный комментарий в боте (≤20 сек) → в мини-аппе админ видит кластеры повторяющихся проблем → отмечает «приняли меры» → бот **адресно уведомляет** всех, кто жаловался на это: «вы писали про X — сделано Y».
**Бонус MAX:** уведомления ботом тем, кто оставил отзыв (замкнутая петля невозможна в анонимной форме), диплинк с контекстом мероприятия.
**MVP:** небольшой. Риск: трудно доказать ценность без реальных данных; «опросник» — распространённая идея, отстройка только через закрытие петли.

### Идея 4. «Не потеряться в кружке» — раннее предупреждение об уходе из доп. образования
**Проблема:** Педагог доп. образования хочет удержать детей, записанных в кружок, но узнаёт об уходе, когда ребёнок уже 3 недели не ходит, а родитель не знает о пропусках, из-за чего дети бросают кружки после первого месяца, а место формально занято.
**Сценарий:** педагог отмечает присутствие в боте кнопками по списку (30 сек) → родитель получает тихое уведомление (`notify:false`) о посещении и обычное — о пропуске → после 2 пропусков бот спрашивает родителя причину (кнопки: болеет / неудобно время / неинтересно / другое) → педагогу сводка «группа риска» с причинами.
**Бонус MAX:** управляемые уведомления, callback-карточки, диплинк записи родителя по QR на первом занятии.
**MVP:** средний. Риск: пересечение с журналами «Навигатора ДО»; ценность держится на данных об оттоке (нужны источники).

### Идея 5. «Маршрут первого дня» — адаптация первокурсника колледжа
**Проблема:** Первокурсник колледжа из другого города хочет в первую неделю закрыть обязательные шаги (общежитие, студбилет, медсправка, пропуск, чат группы), но инструкции разбросаны по сайту и устным объявлениям, из-за чего очереди, повторные визиты и перегруз приёмной одинаковыми вопросами.
**Сценарий:** QR в приёмной/в письме о зачислении → диплинк с кодом группы → персональный чек-лист с дедлайнами и статусами, «где кабинет» (фото/ссылка), напоминания → бот ведёт в чат группы (ссылка) → FAQ с честным «не знаю — вот контакт».
**Бонус MAX:** диплинк с контекстом группы, напоминания, clipboard-кнопки (реквизиты).
**MVP:** простой. Риск: попадает в «навигатор/FAQ-бот» — нужно держать фокус на статусах и дедлайнах, а не на справке.

### Идея 6. «Мост к специалисту» — первичная маршрутизация тревожного сигнала от школьника
**Проблема:** Подросток, столкнувшийся с травлей, хочет тихо сообщить об этом взрослому, но боится огласки и не знает, кто в школе отвечает, из-за чего сигнал не доходит до психолога.
**Сценарий:** бот без диалога «с ИИ»: 3 кнопки уровня срочности → при высокой — сразу контакты Детского телефона доверия / экстренные службы → иначе — передача обезличенного обращения школьному психологу с возможностью ответа через бота.
**Бонус MAX:** двусторонняя переписка через бота без раскрытия номера.
**Оценка:** социально значимо, но высокие риски (ПДн несовершеннолетних, ответственность, дежурство специалиста, пилот сложно проверить жюри). **Для хакатона не рекомендую** как основную.

## Часть 3. Взгляд жюри-скептика

### 3.1 Идеи, которые принесут десятки команд
| Типовая идея | Почему слаба по критериям | Как отстроиться |
|---|---|---|
| **AI-профориентатор** («пройди тест — получи профессию») | Анти-паттерн из ТЗ дословно; ценность недоказуема (рекомендация ≠ результат); галлюцинации; «Билет в будущее» уже есть; UX = длинный опрос | Не «подобрать профессию», а довести до **действия**: запись на профпробу, согласие родителя, напоминание, отметка о посещении |
| **Агрегатор кружков/секций** | Данные либо моки, либо «Навигатор ДО» уже есть; масштабирование = «соберём все данные», что нереалистично; каталог — это не бот | Взять шаг после выбора: запись, удержание, посещаемость |
| **«Навигатор» / FAQ-бот по учебному заведению** | Ценность = поиск по сайту; целостность низкая; LLM без источников | Персональные статусы и дедлайны вместо справки |
| **Чат-бот-психолог на LLM** | Прямо противоречит требованию эскалации к человеку; 152-ФЗ; этический риск; на защите «кто отвечает, если ребёнок напишет о суициде?» | Если трогать тему — только маршрутизация к человеку, без ИИ-терапии |
| **Расписание / замены** | Уже в Сферуме/дневнике; нет проблемы «вне MAX»; тиражирование упирается в интеграцию с АИС, которой нет | Не делать |
| **AI-репетитор / проверка ДЗ** | Не про проблемы трека (доступ, процессы, связь сервисов); сложно показать эффект; зависимость от внешнего LLM → стабильность | Не делать |
| **Геймификация / баллы / рейтинги** | «Функция ради функции», ценность неочевидна | — |
| **Стажировки-агрегатор вакансий** | Дублирует «Работа России», hh; нет данных | Трекер оформления практики (идея 2) |

### 3.2 Чек-лист «красных флагов» для любой идеи команды
1. Формулировка начинается с технологии («AI-ассистент», «платформа», «агрегатор», «навигатор»).
2. ЦА = «школьники», «студенты», «родители» без возраста, роли, ситуации.
3. Нельзя назвать одну метрику, которая изменится у пилота за месяц.
4. Ценность зависит от данных, которых нет, и которые мы «потом интегрируем» (Сферум, дневник, Госуслуги, АИС колледжа).
5. Существующий бесплатный сервис (Сферум «Сбор файлов», Навигатор ДО, Билет в будущее, Работа России) закрывает сценарий на 80% — и команда его не упомянула.
6. Мини-апп — это просто сайт, бот — только кнопка «открыть». Нет ни одного сообщения, которое бот отправляет **по своей инициативе**.
7. «Платформенный бонус» = хаптика/биометрия/QR без причины.
8. Ключевой шаг сценария зависит от Bridge-метода, который не работает в веб-версии, и нет фолбэка (ТЗ требует работу и в мобильной, и в веб-версии).
9. LLM в основном сценарии без фолбэка «не знаю» и без привязки к источникам; внешний LLM-ключ делает демо нестабильным.
10. Несовершеннолетние + свободный текст + ИИ, без описания, кто видит данные и куда эскалация.
11. «Масштабирование» = «добавим больше регионов/пользователей» вместо «ядро + что меняется при переносе».
12. Больше двух ролей в MVP и ни одна не проходится до конца.
13. Нет пилота: не названы организация, владелец процесса, канал распространения.
14. Проверка жюри требует публичного webhook, ручной настройки или реальных аккаунтов, которых нет в слайде 1.
15. Проблема подтверждена только словами «все знают, что…».

## Топ-2 и оценка

Шкала 0–3; итог продукта = взвешенная сумма (масштабирование 35, ценность 25, UX 20, целостность 15), нормировано на 95% без презентации.

| Критерий (вес) | Идея 1 «Допуск» | Идея 2 «Практика без хвостов» |
|---|---|---|
| Масштабирование (35) | **3** — ядро «событие+ростер+форма+статусы» переносится на любой тип организации и мероприятия; шаблоны регионов — переменная часть | **2,5** — переносится на вузы и стажировки, но шаблоны практики сильно зависят от специальности и колледжа |
| Польз. ценность (25) | **2,5** — экономия времени педагога и меньше срывов поездок; риск вопроса «чем лучше Сферум "Сбор файлов"» (ответ: адресные напоминания, живой статус, отметка присутствия, уведомление родителю) | **3** — реальные последствия (незачёт, долги), разрыв между организациями, внешний участник без доступа к системам |
| UX/UI (20) | **3** — родитель: 1 ссылка из чата → 1 экран → готово; педагог: живая доска | **2,5** — 3 роли, у студента ежедневное действие (риск забрасывания) |
| Целостность (15) | **2,5** — чёткий путь от создания до «ребёнок вернулся» | **2,5** |
| **Взвешенно (/3)** | **≈2,79** | **≈2,63** |
| Реализуемость MVP | Высокая: 2 роли, CRUD + планировщик + мини-апп-форма | Средняя: 3 роли, больше состояний |
| Стабильность | Высокая: нет LLM и внешних интеграций, моки только для ростера | Высокая по технике, но сложнее тестовый сценарий для жюри (нужно играть 3 роли; решается тест-переключателем ролей) |
| Платформенный бонус | Убедительно: диплинк + shareMaxContent в чат класса + request_contact + адресные напоминания | Убедительно: диплинк для внешнего наставника + request_contact + напоминания |
| Пилот к финалу | 1 школа, 1 классный руководитель, 1 выезд профминимума | 1 колледж, 1 группа, 1 предприятие — договориться сложнее |

**Рекомендация:** «Допуск» как основная идея. Перед стартом: (1) 5 интервью с классными руководителями/координаторами профминимума; (2) честно разобрать Сферум «Сбор файлов» и показать разницу; (3) уточнить у организаторов, как привязать URL мини-аппа к выданному боту; (4) проверить на живом клиенте `openCodeReader` и `shareMaxContent` в веб-версии и сразу заложить фолбэки.
