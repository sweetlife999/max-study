### Фаза 2 — процессы (ветка `feat/processes`)
**`campus.api`** — FastAPI поверх домена: все 20 операций §7, включая `GET /api/config` и `GET /health` с проверкой БД. Проверка `initData` на каждом запросе (подпись + TTL `auth_date`), согласие по правилу §7, доменные ошибки строго из закрытого списка, `Date` на каждом ответе и `Retry-After` на 429. `docs/openapi.json` экспортируется из самого приложения, CI падает на устаревшем файле.

**`campus.bot`** — один процесс под advisory-lock: long polling с маркером в `kv`, сценарии `/start` (пусто / `org_<token>` / `ev_<id>`), меню, карточка события с RSVP, ввод кода в чат, воркер ротации QR (upload + `PUT /messages`, одна активная display на организатора+событие) и воркер `outbox` (`FOR UPDATE SKIP LOCKED`, 5 попыток с ростом задержки, все 5 типов). Тексты только из i18n.

**Ревью тремя агентами (fastapi / python / security).** CRITICAL по безопасности не найдено: обхода аутентификации, обхода проверки владельца, SQL-инъекций и утечки токена нет; §5 (HMAC-коды, окна, атомарный rate limit) реализован по контракту. Найденное и **исправленное** в этой же ветке:
- **CRITICAL (бот):** пустой long-poll-ответ приходит без маркера, а цикл всё равно ставил чекпоинт — это стирало маркер, и MAX переотдавал всю очередь. Теперь пустая пачка маркер не трогает.
- **HIGH:** 401 от MAX больше не считается ошибкой доставки (иначе вся очередь уходила в `failed` безвозвратно); бот не стартует без `MAX_BOT_USERNAME` (без него QR не собирался никогда); кодом считается только 6 цифр, а не любой текст (десяток случайных сообщений выжигал лимит §5), и режим ввода перестал быть «липким»; подтверждение отметки и принятие приглашения больше не приходят дважды; списки отправляются одним сообщением (25 событий держали бота 25 секунд); при `LOG_LEVEL=DEBUG` SQLAlchemy больше не печатает параметры запросов с кодами, а маскирование ловит форму `"code": "123456"`.
- **MEDIUM:** `Retry-After` от MAX ограничен сверху, иначе один перегруженный чат останавливал polling и ротацию QR на час; списки событий ограничены 200 строками; тело запроса больше 256 КиБ отклоняется до чтения; 500 пишет в лог метод, шаблон маршрута и трассировку; состояние диалога в `kv` живёт 30 минут (раньше токен приглашения оставался там навсегда); Swagger UI выключен.

**Осталось из ревью (не блокирует, вынесено за Фазу 2):** нет общего rate limit на остальных эндпоинтах (нужен на уровне Caddy, а его конфиг появится в Фазе 3); тик `outbox` — одна транзакция на пачку (откат в середине может переотправить уже отправленное); сеть держится внутри открытой транзакции в QR-воркере; `SIGTERM` рвёт пачку без drain; разбор `start`-payload дублирует `domain/deeplinks.py`; 404/405 отвечают формой Starlette, а не конвертом §7 — по контракту это транспортные ответы, решение зафиксировано здесь осознанно.

## Открытые вопросы и риски
- **Мини-приложению нужен публичный HTTPS.** У жюри в Docker без домена оно не поднимется. Надо спросить организаторов, кто прописывает URL мини-приложения и засчитывается ли наш хостинг.
- **Бот привязан к ИНН владельца** и не передаётся вузу: для пилота нужен отдельный бот.
- **Репозиторий к сдаче.** Сейчас в нём лежит `internal/max_bot_from_inna/` — чужой код без лицензии, а ТЗ такое запрещает. Плюс `internal/` и `.claude/notes/` с внутренними исследованиями. До сдачи это надо убрать из репозитория, возможно и из истории.
- **Пилот до 29.10** возможен только на текущих мероприятиях: онбординг первокурсников уже прошёл.
- **Долги из ревью фронта закрыты в PR #5:** экран QR опрашивает событие со счётчиком без списка ФИО; опросы события и явки останавливаются на ошибке; `I18nProvider` обновляет `<html lang>`; сетевая ошибка отметки и ручной повтор покрыты тестом.

## Долги в контракте
- **Контракт противоречит сам себе по `INIT_DATA_TTL_SECONDS`:** §7 называет дефолтом 86400, §10 — 3600 «рекомендация MAX ≈1 час». Код следует §7 (86400). На это указали оба ревьюера: сутки — это окно повторного использования утёкшего `initData`. Решить отдельным PR по контракту: либо 3600 везде, либо убрать 3600 из §10 с обоснованием.
- **Четыре кода из закрытого списка §7 недостижимы по HTTP:** `ambiguous_code` требует запроса без `event_id` (в §7 он обязателен), а `invite_invalid` / `invite_used` / `invite_expired` возникают только на пути бота. Пометить их в §7 как коды бота.

В реализации уже описаны формат `POST /uploads` и точный алгоритм `initData`, но контракт пока отсылает к документации MAX без этих подробностей. После живых проверок перенести подтверждённые детали в `docs/ARCHITECTURE.md`. TTL `initData` (по умолчанию 86400 с), код `not_admin` и осознанный выбор long polling уже зафиксированы в PR #8.
