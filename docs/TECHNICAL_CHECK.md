# Данные для технической проверки

В репозитории нет рабочих токенов и подписанных данных запуска MAX. Для автоматической проверки
`DATA-API.yaml` нужны две переменные:

- `studentInitData` — свежая строка `window.WebApp.initData` студента;
- `organizerInitData` — свежая строка `window.WebApp.initData` организатора.

Передайте значения только через защищённый канал, указанный организаторами хакатона. Не вставляйте
их в issue, чат команды, презентацию, логи CI или коммит. Сервер принимает данные запуска не дольше
3600 секунд, поэтому получите обе строки непосредственно перед проверкой. Старые значения ожидаемо
дают `401 invalid_init_data`.

## Подготовка ролей и события

1. Откройте `https://max.ru/se13836036_1_bot?startapp` в аккаунте студента, примите согласие и
   сохраните свежий `window.WebApp.initData` как `studentInitData`.
2. В отдельном аккаунте один раз откройте выданную владельцем бота одноразовую ссылку организатора,
   нажмите «Начать», затем снова откройте мини-приложение и примите согласие. Одноразовая ссылка
   передаётся тем же защищённым каналом и не хранится в репозитории.
3. Используйте выделенный тестовый аккаунт организатора и оставьте у него ровно одно событие. Оно
   должно начаться не более 30 минут назад и закончиться минимум через 30 минут. `GET
   /api/org/events` сортирует события по `starts_at` и `id` в обратном порядке, а DATA-API берёт
   `$.items[0].id`; отсутствие других событий делает выбор однозначным и воспроизводимым. Сохраните
   свежий `window.WebApp.initData` как `organizerInitData`.

На MAX Web значение можно получить из консоли разработчика внутри открытого мини-приложения командой
`copy(window.WebApp.initData)`. На мобильном клиенте используйте перехват запроса к собственному API
на доверенном тестовом устройстве или временно откройте тот же аккаунт в MAX Web. Не отправляйте
`initDataUnsafe`: API проверяет подпись именно полной строки `initData`.

## Повторный прогон

Cleanup закрывает отметку у выбранного события. Повторный полный прогон с тем же студентом безопасен:
`POST /api/checkins` вернёт `200` и `already=true`, не создаст вторую запись и не начислит баллы
повторно. Получите новые `studentInitData` и `organizerInitData`, если с момента запуска прошло около
часа.

Проверка требует доступности MAX, публичного `https://max.fblrkus.ru`, DNS/TLS и PostgreSQL. Работа
камеры и внешний вид мини-приложения проверяются вручную в MAX mobile и MAX Web; DATA-API проверяет
HTTP-сценарий без камеры.
